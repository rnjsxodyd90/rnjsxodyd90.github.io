파이썬 dict에서 값 꺼낼 땐 item['key']보다 .get()

item['key']는 키가 없으면 그냥 죽어버린다. .get()은 None을 돌려준다. 그 차이가 생각보다 크다.

파이썬 처음 배울 때 딕셔너리에서 값 꺼내는 거 다 이렇게 배운다.

value = item['key']

근데 이거, 키가 없으면 그냥 KeyError 나면서 죽어버린다.

user = {'name': 'Tae'}
user['email']  # KeyError: 'email'

문제는 실제 코드에서 딕셔너리가 항상 우리가 원하는 키를 다 갖고 있다는 보장이 없다는 거다. API 응답 받아서 파싱하거나, 설정 파일 읽거나, JSON 다룰 때 그 키가 있을 수도 있고 없을 수도 있다.

.get()을 쓰면

user.get('email')          # None
user.get('email', 'n/a')   # 'n/a' (기본값 지정)

키가 없으면 그냥 None을 돌려준다. 죽지 않는다. 기본값을 주고 싶으면 두 번째 인자로 넘기면 된다.

그래서 뭐가 좋냐

if 'email' in user 같은 체크를 따로 안 해도 된다는 게 크다.

# 이거 대신
if 'email' in user:
    email = user['email']
else:
    email = None

# 이거 한 줄
email = user.get('email')

코드도 짧아지고, 깜빡하고 키 체크 안 해서 프로덕션에서 KeyError 터지는 일도 없다.

그럼 item['key']는 언제 쓰나

키가 무조건 있어야 하는 상황. 없으면 그건 진짜 버그라서 빨리 터지는 게 나은 경우. 예를 들어 자기가 방금 만든 딕셔너리에서 값 꺼낼 때라든가, 스키마가 보장된 내부 데이터라든가. 그땐 KeyError로 빨리 죽는 게 디버깅에 도움이 된다.

반대로 외부에서 들어오는 데이터 (API, 파일, 사용자 입력) 다룰 땐 거의 항상 .get()이 답이다.
